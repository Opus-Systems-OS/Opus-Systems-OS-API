# Unity sample — JarvisSample

A Unity 6 project that is the smallest possible fleet client: a key, a text
box, a Send button, and the reply streaming in over the session WebSocket.
It runs in Play mode in the editor with no headset. The Quest app grows from
here: swap the IMGUI for a world-space panel and the text box for speech.

- The SDK comes in as the UPM package `com.opussystems.api` (git URL in
  `Packages/manifest.json`, source in `sdk/upm/com.opussystems.api` — a
  copy of `sdk/csharp` kept current by `sync-sdk.sh`; CI checks it).
- `Assets/Sample/JarvisConsole.cs` — the client. One rule for the SDK in
  Unity: callbacks arrive on background threads, so queue them and apply in
  `Update()`.
- `Assets/Sample/JarvisSample.unity` — generated by
  `SampleSceneBuilder.Build`; a camera and one GameObject with the console.
- `Assets/Tests/EditMode` — the SDK under Unity's runtime; the live test
  needs `OPUS_API_KEY`.
- `Assets/Tests/PlayMode` — a real jarvis turn over the WebSocket with
  deltas; needs `OPUS_API_KEY` and `OPUS_LIVE_SESSION=1` (a few cents).

Dependencies (in `Packages/manifest.json`): `com.unity.nuget.newtonsoft-json`,
`com.unity.test-framework`. Editor 6000.6.x.

## Run

Open `JarvisSample` in Unity Hub, open the scene, press Play, paste an
`osk_…` key with `sessions:read,sessions:write`, Send. Or headless:

```sh
U=/Applications/Unity/Hub/Editor/6000.6.2f1/Unity.app/Contents/MacOS/Unity
cd sdk/unity/JarvisSample
"$U" -batchmode -nographics -projectPath "$PWD" -executeMethod SampleSceneBuilder.Build -quit
OPUS_API_KEY=osk_… "$U" -batchmode -nographics -projectPath "$PWD" -runTests -testPlatform EditMode -testResults /tmp/edit.xml
OPUS_API_KEY=osk_… OPUS_LIVE_SESSION=1 "$U" -batchmode -nographics -projectPath "$PWD" -runTests -testPlatform PlayMode -testResults /tmp/play.xml
```

Verified 2026-09-18 on Unity 6000.6.2f1: EditMode 3/3 (incl. live
`MeAsync`/`RigAsync`), PlayMode 1/1 — session created, socket opened with
deltas, "23 times 3 is 69." streamed then confirmed by the `agent.message`.

## Toward the Quest

- Add the **Android Build Support** module in Unity Hub and the Meta XR /
  OpenXR packages; the SDK has no platform code.
- Keys: a headset gets its own `osk_` key (`sessions:read,sessions:write`,
  plus `inference` if it will use the rig). Store it in Unity's
  `PlayerPrefs` only for prototypes; a real app should keep it in the
  Android Keystore.
- Tools the headset runs itself (hand pose, room anchors, whatever the app
  exposes) are declared on the session as `CreateSessionRequest.Tools` and
  answered with `SessionSocket.SendToolResultAsync` — exactly what the
  native Mac Jarvis app does with Apple Music.
